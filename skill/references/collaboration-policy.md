# Chat / Codex collaboration policy

One policy for the local C2C entry, its templates, and user-maintained global guidance. This replaces conflicting workflow defaults prospectively; historical records remain historical. Platform security, access controls and explicit privacy restrictions remain effective.

## Ownership and delegated decisions

Chat investigates, plans and reviews. Codex.app is the daily single repository writer; available Chat write tools do not change that default. Explicit user assignments may name another executor for a bounded exception; record actual executor evidence and that exception, without changing the future default. C2C capability is not authority.

Maintain one writer per resource. Transfer ownership at a safe checkpoint with current state and remaining work; do not repeat completed actions. A concrete instruction from the bound Chat within the user's delegation authorizes Codex's scoped investigation/edit/test/fix/verification cycle without another human ratification. Do not manufacture a gate per file, test, candidate or routine review. Include intended commit, push and publication effects in the scoped assignment; capability alone is not authorization.

Send conflicts with older instructions to Chat with the exact source, affected action and smallest resolution. Chat resolves routine workflow conflicts within scope. Do not disable validators, relabel failures or change an unauthorized contract. Continue unaffected safe work. Chat alone asks the user about merge, unauthorized material scope expansion, destructive operations, unexpected sensitive disclosure or platform consent that must be completed personally. Platform approval prompts remain binding. An access denial is not authority to switch tools, agents or surfaces; preserve the rejection and use a supported installation/configuration or formal clearance route.

For an explicitly authorized, bounded Chat/Codex task, generic OMX/engineering workflow defaults do not restart completed requirements interviews, design approvals or routine human approval loops. Continue the admitted work and relevant verification; real scope, platform and safety boundaries remain effective. This is a scoped applicability rule, not a blanket override of OMX.

## Approved task pipeline and supporting methods

Confirm the original goal and current state from available evidence; reuse a completed, bound clarity/interview artifact instead of restarting discovery. Chat investigates and plans; C2C hands scoped implementation to the assigned Codex writer. Missing material intent goes to Chat while unaffected work continues. Generic deep-interview/autopilot/ralplan gates do not repeat already-completed stages inside this accepted C2C task.

At the first meaningful failure, invoke Progressive Investigation: preserve the observed failure and baseline, distinguish hypotheses from facts, select the smallest discriminating probe, identify the supported cause to sufficient depth without treating the first plausible cause as proven, and reconcile the finding with the original goal and affected context. Before a new attempt, record new evidence and a changed hypothesis or strategy; no identical blind retry. An existing applicable final-wave cap bounds that authorized attempt; it neither authorizes an automatic second wave nor imposes a universal cap on every first error. If no justified next strategy exists, return the concrete blocker to Chat. Access/security denials require formal clearance and never authorize an alternate route.

Use Ponytail simplification, debugging and testing as narrow methods within this pipeline: reuse existing/native solutions, fix the evidenced root cause, keep relevant runnable checks, and preserve security and error handling. Its report exception permits the requested evidence and walkthrough in full. Generic terse-output, interview, review or full-suite defaults do not replace the C2C ownership, cumulative Chat review or relevant-check contract. This applicability rule does not disable plugins or hooks.

Implementation verification, Chat's seven-axis cumulative review and merge eligibility are distinct. Preserve numeric iteration/checkpoint and already-sent receipt state; a repair is scoped work under the current delegation, not a new interview or publication approval.

## Evidence and system review

Use the intended authorized repository and a pushed commit as primary durable file evidence. Return repository, SHA, relative paths and relevant summaries. A local-only commit has no remote GitHub record. Authorized Remote Desktop Commander may read exact necessary local paths after device/workspace confirmation; this observation is neither a GitHub record nor fully offline processing. Correctly bound C2C metadata remains useful. Do not attach/drag workspace files, upload archives, paste source/raw logs or substitute external sharing links. Do not retrieve a withheld body through another tool.

Before committing, inspect status/index, stage explicit paths, honor ignore rules without force-add, and review the staged diff for scope and sensitive content. Tracked sensitive files are not protected by .gitignore. Never push local policies or private evidence to a third-party upstream. Reconcile ambiguous writes by readback before any retry.

Chat starts from the original requirements and reads actual changes plus necessary context. Check both directions: every change serves a requirement, and every important requirement has implementation and verification. Trace affected interfaces, callers, state transitions and workflow prerequisites proportionately. A Codex report, matching digest or green local test is evidence of one claim, not proof of system correctness. Reuse valid checks; do not reread the whole repository or rerun unrelated suites for formal completeness. Report fit to the original goal, affected system/scope, evidence, unresolved risks and the next authorized action.

## Merge and completion

Codex sends a merge candidate to Chat. Chat reads original requirements, cumulative actual changes and affected context, then requests user approval of the exact PR/head. Merge runs only through the explicitly assigned executor under that exact-head approval, with result readback. Available tools do not assign merge ownership. A changed head requires renewed review and approval. This policy alone authorizes no merge.

Completion requires requested behavior plus relevant system constraints, supported verification and disclosed limitations. Distinguish candidate preparation, saved configuration, actual host loading and behavioral results. Cloud plugin publication belongs to Chat; local edits do not imply cloud synchronization. Use one primary workflow and task-loaded supporting references rather than restarting multiple approval ceremonies.


## Full records and overall drift

In this collaboration, unqualified 飄移 / drift always means overall drift: assess the original goal, all cumulative changes, and the entire affected system and workflow. This includes work direction, priorities, and whether governance work has displaced the original deliverables. Use the existing seven axes; this clarification adds no axis, workflow, approval gate or authority. A useful scoped technical review remains partial and must not answer the overall question. Latest-patch alignment or green checks alone cannot support an overall no-drift conclusion. If evidence needed for the whole assessment is missing, the overall verdict is UNKNOWN unless already-read evidence establishes material DRIFT_FOUND; never present a scoped PASS as an overall verdict.

Use [the canonical format](full-format.md), version 1.0.1 / package 0.3.3, for full WORK_ORDER, EXECUTION_RESULT and CHAT_REVIEW. Keep numeric checkpoint iteration and a separate repair label; unknown executor remains UNKNOWN and planning head may be null with a reason. Full sanitized records belong on the authorized owning GitHub issue/PR only when destination and publication authority are verified; otherwise prepare the full record in the existing authorized conversation, mark its durable link UNKNOWN, and report that limited delivery gap. Local evidence may supplement the conversation record; it is not a prerequisite. Short C2C messages carry pointers, never invented URLs. Preserve the existing checkpoint/schema and do not resend EXECUTED_SENT results. Codex actively asks the exact drift question. Chat reads the original goal, cumulative diff and affected context and gives evidence-backed judgments on all seven axes; green tests alone cannot establish PASS.
